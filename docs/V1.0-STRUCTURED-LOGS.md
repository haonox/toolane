# V1.0 结构化日志

`toolane serve` 将每条服务日志作为一行 JSON 写入标准错误输出。日志用于把一次 HTTP 请求关联到已接受的任务、Workflow，以及后续状态变化；不代替 SQLite 中的执行记录或事件。

- `http_request` 包含服务生成的 `request_id`、请求方法、固定路由模板、HTTP 状态和处理耗时。认证成功后才包含 `tenant_id`；任务或 Workflow 通过授权检查后才记录相应 ID。跨租户查询返回 `404`，不会记录被猜测的资源 ID。错误响应还记录稳定 `error_code`。
- `execution_transition` 在状态或清理状态成功提交后记录 `execution_id`、`workflow_id`、`tenant_id`、前后状态、清理状态和稳定错误码。状态日志经容量为 1024 的通道异步写入，避免在 Manager 状态锁内执行日志 I/O；通道满时丢弃该条日志，进程正常退出时输出 `transition_logs_dropped` 计数。SQLite 记录和指标不受日志丢弃影响。
- `recovery_complete` 报告启动时核对的资源数和仍待删除的资源数。后续确认删除会输出 `recovered_cleanup_confirmed` 和对应 Execution ID。`service_ready`、`metrics_ready` 分别报告实际监听地址。

日志不记录原始 URL、Bearer Token、幂等键、请求参数、脚本、stdout/stderr 或完整结果。SSE 请求在连接结束时记录一次，`duration_ms` 包含订阅持续时间。日志以进程标准错误输出为边界；如需长期保留或轮转，应由部署环境处理。

验证覆盖认证失败、成功准入、跨租户查询、SSE、Workflow ID 关联、JSON 格式与敏感内容排除。运行：

```bash
go test ./internal/httpapi ./cmd/toolane
go test -race ./internal/httpapi ./cmd/toolane
```

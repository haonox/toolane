# V0.3 第一批：沙箱资源准入

本批把沙箱 CPU、内存预算接入现有 Manager；尚未接入 Docker Executor。真实容器的创建、隔离、日志和回收将在后续 PR 实现并单独验收。

## 行为

- 服务端注册工具时可设置 `tool.Definition.Resources`，使用 `CPUMilli` 和 `MemoryBytes` 表示每次运行需要预留的沙箱资源。两个字段同时为零表示 Mock 或可信 Process 不占沙箱预算；非零时两个字段都必须为正。请求方不能提供或扩大这些值。
- 默认单任务上限为 1000 millicores、256 MiB；全局预留总预算为 4000 millicores、1024 MiB。配置在 Manager 创建时校验，单个工具需求超过上限的提交直接返回 `ErrSandboxBudgetExceeded`。DAG 中任一节点超限，整个批次拒绝。
- Worker 在 Manager 锁内检查全局槽位、租户运行限额及沙箱 CPU/内存可用量，认领时同步预留。资源暂时不够的任务留在就绪队列；调度器可以认领后面放得下的任务。资源释放会唤醒等待的 Worker。
- Executor 收到相同数值的 `RunOptions.SandboxResources`。正常完成、执行失败、取消或超时且后端确认停止后，Manager 释放预留。`StopUnconfirmed` 保持 `cancelling`、运行槽位及预留，并暂停新任务准入。
- `Snapshot` 记录任务采用的沙箱 CPU/内存需求；`Stats` 报告当前预留量。这是准入预算，不代表已经在宿主机或容器运行时验证了硬限制。

## 验证

`TestSandboxBudgetSkipsUnfitReadyWork` 在 FIFO 和租户轮询两种模式下验证：内存放不下的任务保持排队，后面的较小任务可启动；资源释放后前者启动，结束时预留归零。另有整批拒绝和停止无法确认时保留预留的测试。常规检查：

```bash
go test ./...
go test -race ./...
go vet ./...
```

这些测试不依赖 Docker。真实容器测试尚未建立，不能把这里的通过结果视为隔离验收。

# V1.0 第一批：SQLite 存储基础

这一批增加 `internal/store/sqlite`，为 Execution Manager 接入持久化准备事务边界。初始合并时 CLI 和 Manager 尚未调用该存储；后续进展见[第二批幂等准入](./V1.0-IDEMPOTENCY.md)和[第三批单任务持久化运行路径](./V1.0-DURABLE-SINGLE.md)。

## 选择和平台

- 使用 Go `database/sql` 与 `modernc.org/sqlite` v1.60.1。标准库没有 SQLite 驱动；这个驱动无需 CGO，本项目保留 Go 1.27.1 构建要求。
- 状态目录锁使用 Linux `flock`，因此本批存储只在 Linux 上打开。其他系统会返回明确错误。锁是协作式的，服务必须统一通过 `Open` 使用此目录。
- 状态目录要求仅所有者可访问，数据库文件创建为 `0600`。同一个目录只能被一个打开的 Store 占用。进程崩溃后内核自动释放锁，锁文件无需删除。

## Schema v1

`PRAGMA user_version` 记录版本。首次打开在一个事务中建立 `executions` 和 `execution_events`；版本高于当前程序时拒绝打开，避免旧程序修改新 schema。事件以 `(execution_id, sequence)` 为主键，通过外键归属任务。

数据库使用 WAL、`synchronous=FULL`、外键检查与单连接写入。`CreateExecution` 将任务和首个事件一起提交；`Transition` 用版本号比较更新任务并追加事件。任一写入失败都回滚整个事务。`EventsAfter` 按序读取已提交事件，为后续 SSE 回放提供基础。Store 不判断合法状态转换；这仍由 Manager 负责。`Snapshot` 与 `Request` 由未来接入层编码，存储层保留原始字节。

第一批合并时，这些方法尚未提供在线任务的持久性保证，因为 Manager 当时没有调用它们。第三批的单任务接入遵循相同事务边界：接受响应等待创建事务成功，状态发布等待状态与事件事务成功；工具调用不放在数据库事务内。

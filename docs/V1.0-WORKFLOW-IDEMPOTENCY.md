# V1.0 第七批：Workflow 幂等提交

持久化 Manager 增加 `SubmitWorkflowIdempotent(ctx, request, key)`。调用方须从可信身份确定租户；该 Go API 尚不是 HTTP 认证入口。`NewManager` 的内存模式拒绝幂等提交。

## Schema v4 与事务

SQLite 新增 `workflow_idempotency`，以 `tenant_id + endpoint + key` 为主键，通过外键保护仍被有效键引用的 Workflow。v3 数据库打开时事务化迁移到 v4，保留原有 Workflow、Execution 与事件。

首次提交将 Workflow、全部节点 Execution、首事件、依赖关系及幂等键放在一个事务中；任一写入失败则整批回滚。有效期为首次成功提交后的 24 小时。有效期内等价请求返回原 Workflow ID，请求不同返回 `ErrIdempotencyConflict`；过期后可重用键，旧 Workflow 不会因键到期自动删除。数据库唯一约束裁决并发提交。

幂等比较使用校验后的租户、节点提交顺序、节点 ID、排序后的直接依赖，以及每个节点的规范化工具请求。工具参数 JSON 的对象字段顺序和空白、与默认值等价的超时配置不影响比较；节点提交顺序仍会影响比较。规范化沿用单任务实现，数字的不同词法形式仍视为不同输入。

Manager 在检查容量前查询有效键，因此容量已满时的重复提交仍可返回原批次。查询只是快速路径，真正的并发裁决在创建事务内完成。重启后仍可用相同键取得原批次。幂等提交防止重复创建工作流，不保证工具外部副作用恰好执行一次。

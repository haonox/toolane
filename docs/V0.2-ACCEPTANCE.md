# V0.2 自动化验收记录

2026-10-18 在 Linux amd64、Go 1.27.1 上，基于已合并 DAG 与租户调度的 `main`（`b2ce1d0`）执行收尾检查。V0.2 的进程内范围为 DAG 校验和依赖调度、租户配额、默认轮询调度、原子批次准入及 FIFO 对比实验。

| 验收项 | 自动化证据 | 结果 |
| --- | --- | --- |
| ACC-08：无效 DAG 整批拒绝 | `TestWorkflowInvalidGraphsRejectWholeBatch`、`TestWorkflowCapacityRejectsWholeBatch`、`TestTenantPendingLimitRejectsWithoutPartialWorkflow` | 通过；无部分记录或执行 |
| ACC-09：失败传播与独立分支 | `TestWorkflowDependencySuccessFailureAndIndependentBranch` 等工作流测试 | 通过；受影响下游跳过，独立分支继续 |
| ACC-10：持续提交下的公平机会和配额 | `TestTenantContinuousSubmissionDoesNotStarveOtherTenant`、`TestTenantRunningLimitSkipsSaturatedTenant`、`TestTenantRoundRobinAndFIFOOrder` | 通过；A 占满 64 个待启动额度并持续重试时，B 在 A 积压未排空前获认领，额度没有越界 |

收尾测试使用受控的 Mock 执行器：先让 A 租户积压 64 个任务，再让 A 持续提交并观察到至少 20 次明确的租户容量拒绝；释放 Worker 后，A 可补入新任务，而 B 在最多一次 A 认领后启动，当时 A 仍有至少 63 个待启动任务。任务完成后待启动、运行和活跃租户计数均归零。该测试在竞态检测下单独重复 50 次通过。

执行命令及结果：

```bash
go test -count=1 ./...                                      # 通过
go test -race -count=1 ./...                                # 通过
go test -race -count=10 ./internal/execution                # 通过
go test -race -count=50 -run TestTenantContinuousSubmissionDoesNotStarveOtherTenant ./internal/execution # 通过
go vet ./...                                                # 通过
go run ./cmd/toolane                                        # Mock 演示成功
go run ./cmd/toolane process                                # Process 演示成功
go run ./benchmarks/scheduler -out /tmp/toolane-v02-final-acceptance -repetitions 3 -seed 20261018
```

FIFO／轮询实验复跑成功：四类负载、两种策略、每组 3 次，每次 72 个请求，共 1728 次提交全部接受，拒绝数为 0。前 24 次认领的 Jain 指数在本次运行中，FIFO 为 0.649～0.667，轮询为 0.970～1.000。原始实验方案、提交的逐任务数据及测量限制见 [调度说明](./V0.2-SCHEDULER.md)。短时 Mock 负载只支持调度机会的结论，不代表生产吞吐或通用延迟保证。

上述结果满足需求书所列 V0.2 退出条件。V0.2 的租户 ID 由可信进程内调用方提供；Docker 沙箱与资源预算属于 V0.3，HTTP 身份认证、跨租户访问控制和持久化属于 V1.0，均不在本次验收范围内。

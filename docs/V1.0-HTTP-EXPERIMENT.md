# V1.0 本地 HTTP 服务负载实验

本实验验证已实现的本地 HTTP、SQLite 持久化和租户轮询调度路径。使用 `mock.delay`，不涉及 Docker、沙箱创建开销或真实容器吞吐。数据只是当前机器和配置下的基线，不是服务容量承诺。

## 复现

需要 Go 1.27.1、Python 3 标准库，以及可监听本机回环地址的权限。在项目根目录执行：

```bash
GOPROXY=off GOCACHE=/tmp/toolane-v10-go-cache \
  go build -o /tmp/toolane-http-benchmark-bin ./cmd/toolane
PYTHONDONTWRITEBYTECODE=1 python3 benchmarks/run_http_service.py \
  --binary /tmp/toolane-http-benchmark-bin \
  --out /tmp/toolane-http-benchmark-repeat \
  --repetitions 3 --seed 20261020 --interval-ms 2
```

启动器在 0700 临时目录内创建全新 SQLite 状态和 0600 私有配置，生成三个随机 Token，启动本地服务，完成实验后发送 SIGTERM 并移除临时目录。Token 不写入原始数据。输出目录必须不存在或为空。启动异常时输出服务日志末尾；中途失败的输出不视为有效实验。

`benchmarks/http_service.py` 也能连接自行启动的本地服务，需分别设置 `TOOLANE_TOKEN_A/B/C`，并提供 `--base-url`、`--metrics-url` 和 `--out`。`--server-pid` 可选；不提供时不采集 Linux `/proc` CPU 和 RSS。访问地址只接受回环地址，HTTP 客户端不跟随重定向，也不继承代理。默认实验提交 864 个有界 Mock 任务，重复次数限制为 1–10；建议仅对独立的测试状态目录运行。

## 方法与指标

- 每个场景重复三次，每次先为 A/B/C 各提交 2 个 2 ms 预热任务，之后测量 72 个任务。随机种子为 20261020，租户和时长排列可由脚本复现。
- 全部批次使用同一个服务进程和状态目录，历史终态记录会累积；每批计数和延迟按该批任务单独计算。
- 短任务均为 2 ms；长任务均为 15 ms；混合场景各 36 个；突发场景为 50 ms，A/B/C 数量分别为 48/12/12。
- 前三个场景按 2 ms 计划间隔串行提交；突发场景无计划间隔、按 A/B/C 分组提交。客户端必须等一个 POST 返回才发下一个。这个模型有计划到达时间，但不是独立并发到达流；`schedule_lag_ms` 显示客户端落后计划的程度。不能把测得吞吐当作服务极限。
- CSV 中一行对应一次提交。拒绝保留 HTTP 状态与错误码；接受任务再查至终态。`queue_ms = running_at - created_at`，`total_ms = finished_at - created_at`。`execution_ms` 对 Mock 使用 `running_at` 起点，因为没有后端进程启动时间；`ready_wait_ms` 因无 `process_started_at` 留空。百分位采用最近秩法，分别对每批接受并结束的任务计算。
- `scheduled_at` 为相对该批起点的计划秒数；`submit_started_at` 等字段是 UTC 时间戳。二者不可直接相减，计划偏差已经记录为 `schedule_lag_ms`。
- `completed_per_second` 为该批接受且结束的任务数除以从首个计划提交到最后一个任务查到终态的客户端墙钟时间。它包含串行提交与轮询开销。`metadata.json` 保存各批次前后的指标、`/proc` CPU 时间和 RSS 快照；两端快照不是峰值。Goroutine 数来自管理端口。
- 三租户等量的前三类场景可直接看各租户等待分布；突发场景的任务数量和成本不等，不能据此计算或解释 Jain 公平指数。FIFO 与轮询的同条件对照见 V0.2 [调度实验](../benchmarks/scheduler/main.go)；此处服务只运行轮询策略。

## 2026-10-20 本机记录

主机为 Intel Core i5-8400、6 核，Linux 7.0.0-38-generic，Go 1.27.1，Python 3.14.4。服务为默认配置：4 Worker、全局待执行上限 256、每租户待执行上限 64、每租户运行上限 2；状态目录每次实验全新。实验入口对应 `main` 的 `ad0481e` 加本批尚未提交的指标改动，服务二进制 SHA-256 见 `metadata.json`。完整原始数据在 [`benchmarks/results/v10-http-mock-2026-10-20/`](../benchmarks/results/v10-http-mock-2026-10-20/)。

| 场景 | 接受 / 提交 | 拒绝 | 成功 / 接受 | 总延迟 P50 范围 | 总延迟 P95 范围 | 批次完成率范围 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 短任务 | 216 / 216 | 0 | 216 / 216 | 2.91–3.18 ms | 3.59–4.24 ms | 343–350/s |
| 长任务 | 216 / 216 | 0 | 216 / 216 | 45.55–86.80 ms | 85.63–154.69 ms | 202–233/s |
| 混合 | 216 / 216 | 0 | 216 / 216 | 16.23–28.97 ms | 39.23–50.12 ms | 335–379/s |
| 突发 | 216 / 216 | 0 | 216 / 216 | 453.72–457.54 ms | 1243.63–1302.58 ms | 49–51/s |

范围是三次独立批次中各自百分位或完成率的最小至最大，不是把三次样本混合后重新计算。每批 P99、各阶段耗时、计划偏差、终态和资源快照见 `summary.json`、`executions.csv`、`metadata.json`。例如突发场景三次的排队 P95 为 1192.55–1251.24 ms；负载造成可观测排队。长任务第二、三次的最大提交计划偏差为 91.9 ms 和 74.0 ms，因此这些批次不能作为精确 2 ms 开环到达的结果。所有批次前后空闲快照的 Goroutine 数为 16；末次突发批次结束后 RSS 为 24.10 MiB。没有采集峰值 Goroutine、峰值 RSS 或容器资源指标。

## 输出文件

| 文件 | 内容 |
| --- | --- |
| `executions.csv` | 864 次提交及接受任务的状态时间戳和分段耗时 |
| `summary.json` | 每场景每次运行的接受、拒绝、终态、吞吐与最近秩 P50/P95/P99 |
| `metadata.json` | 版本、机器、负载参数、脱敏服务配置及前后 CPU/RSS/Goroutine 快照 |

下一轮验收需单独记录真实 Docker 的受限任务、容器清理与服务崩溃恢复；这些结果不能用本 Mock 实验推断。

代码检查可运行 `python3 -m unittest discover -s benchmarks -p 'test_http_service.py' -v`、`go test ./...` 和 `go test -race ./internal/observability ./cmd/toolane`。

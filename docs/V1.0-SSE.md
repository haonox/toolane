# V1.0 执行事件 SSE

本批新增 `GET /api/v1/executions/{id}/events`。请求沿用服务配置文件中的 Bearer Token，只有任务所属租户可以订阅；跨租户 ID 返回 `404`。当前 `toolane serve` 仍只注册 `mock.delay`，因此示例服务的任务没有 stdout/stderr。Go 调用方注册其他工具后，其受限输出也会记录为事件。

```bash
curl -N -H 'Authorization: Bearer YOUR_TOKEN' \
  http://127.0.0.1:8080/api/v1/executions/EXECUTION_ID/events
```

每个事件使用该任务内递增的十进制 `id`，以及 `state`、`progress`、`resource_created`、`output` 或 `end` 类型。`data` 是 JSON，包含 `at` 时间戳。`output` 的 `data` 另含 `stream`（`stdout`/`stderr`）和 `chunk`；每块不超过 4096 个 UTF-8 字节，每个任务最多保存 1024 个输出事件。当前输出事件在工具返回后、终态事件写入前统一落库；运行期间的状态变化会实时推送。输出采集本身仍受原有的任务字节上限约束。`end` 表示终态已提交，客户端随后应查询任务快照获取完整结果和清理状态。

断线后，将最后处理成功的 `id` 放入 `Last-Event-ID`，服务只回放其后的事件；也可以从 `0` 开始。客户端应按事件 ID 去重。服务先注册一个容量为 1 的非阻塞唤醒信号，再分批读取 SQLite 中已提交的事件，故回放和实时事件交界不会遗漏。每次最多读取 128 条，慢客户端只影响自己的连接；每次写入有 5 秒期限，15 秒空闲时发送注释心跳。

```bash
curl -N -H 'Authorization: Bearer YOUR_TOKEN' \
  -H 'Last-Event-ID: 3' \
  http://127.0.0.1:8080/api/v1/executions/EXECUTION_ID/events
```

默认每租户最多 8 条 SSE 连接、全服务最多 64 条。服务配置可用 `sse_tenant_limit` 和 `sse_global_limit` 覆盖；前者必须为正，后者不得小于前者。超额返回 `429/sse_limit_exceeded`。无效或超前的游标返回 `400/invalid_event_id`。如果任务还在但请求游标之前的事件已缺失，握手返回 `410/event_history_expired`，调用方应改查 `GET /api/v1/executions/{id}`。保留策略会将终态任务与事件一起删除；整条任务已被删除时返回 `404`，没有可查询的快照。

验证命令：

```bash
go test ./internal/store/sqlite ./internal/execution ./internal/httpapi ./cmd/toolane
go test -race ./internal/httpapi ./internal/execution ./internal/store/sqlite
```

测试覆盖输出分块和回放、游标、跨租户拒绝、实时交界无重复或缺口、连接上限、慢客户端不阻塞 Worker、历史缺失握手，以及输出事件批次写入失败时整批回滚。

# V0.3 第二批：Docker Shell Executor

本批实现固定镜像的 Shell 脚本沙箱，并接入现有 Manager。对应 REQ-SANDBOX、REQ-CLEAN 及 ACC-11 中的基础隔离与输出限制；容器删除失败、后端失联的故障注入和后台残留回收仍需后续批次完成，不能据此宣称 V0.3 整体验收通过。

## 进程内接入

管理员注册工具时构造 `docker.ScriptDefinition`，提供固定的 `ImageTag`、`ImageDigest` 和稳定的 `InstanceID`。镜像必须事先拉到本地；执行器使用 `--pull=never`，不会替调用方下载镜像。镜像标签和 digest 必须指向同一份本地镜像。

```go
definition, err := docker.ScriptDefinition("sandbox.shell", docker.Spec{
    ImageTag:    "alpine:3.24.2",
    ImageDigest: "sha256:294b683cb724975bec92580e1e685676bd4b50bda910ddb8c51d4cabeaec77e6",
    InstanceID:  "local",
})
if err != nil {
    return err
}
if err := registry.Register(definition); err != nil {
    return err
}
```

任务参数只允许形如 `{"script":"printf 'hello\\n'"}` 的 JSON 对象。脚本在容器内由 `/bin/sh -c` 执行；它属于不可信输入，不进入宿主 Shell。工具的资源请求与调度预留必须一致。管理员负责给运行服务的账户配置 Docker 访问权限，并确保该账户及 Docker daemon 均可信。

## 创建、运行与清理

- 启动前检查 Docker cgroup v2、seccomp 和本地镜像；创建后检查容器镜像 ID、非 root 用户、只读根目录、禁网、PID/IPC/cgroup namespace、能力集、权限选项、CPU/内存/swap/PID 上限、tmpfs、挂载、设备、端口及日志配置，检查失败则不启动。
- 容器禁用持久 Docker 日志。stdout/stderr 在 Go 中共享字节预算；达到上限时请求停止。工作区是 64 MiB 的容器 tmpfs，计入 256 MiB 内存限制；默认 CPU 为 1000 millicores，PID 上限为 64，swap 不额外扩容。
- 执行结束、取消、超时或输出超限后，用独立的有界 Context 停止并删除本任务容器。每个容器有项目、实例、Execution 归属标签；清理前验证标签。删除失败单独记入 `cleanup_status` / `cleanup_error`，不覆盖执行结果。停止状态无法确认时保持 Manager 的运行预留并暂停新任务准入。
- 当前任务记录仅在内存中；进程崩溃或 Docker 长时间失联后，尚无后台扫描和残留上限控制。这是下一批工作，不能依赖本批自动恢复。

## 验证

本地单元与静态检查：

```bash
go test ./...
go test -race ./...
go vet ./...
```

真实容器测试要求 Linux、可访问的 Docker Engine 与预先拉取的 `alpine:3.24.2@sha256:294b683cb724975bec92580e1e685676bd4b50bda910ddb8c51d4cabeaec77e6`。以下命令仅在本机配置需要 `sudo` 访问 Docker 时使用；它运行四个受限容器测试，并在每个测试结束时检查和清理本次实例的容器：

```bash
sudo env PATH="$PATH" GOCACHE=/tmp/toolane-v03-go-cache go test -tags=integration ./tests/integration/... -v
```

2026-10-18，Linux amd64、Docker 29.9.1、cgroup v2、内建 seccomp 下，上述四项真实测试通过：非 root/只读根目录/禁网与工作区写入、非零退出码、输出洪泛停止、执行超时停止。单元测试另覆盖启动前策略拒绝和容器删除错误独立记录。真实 OOM、删除失败与后端失联的故障注入尚未完成。

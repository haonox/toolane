# V1.0 管理指标

`toolane serve` 可通过可选的 `metrics_listen` 启动独立的本地管理监听。将它加入私有服务配置文件：

```json
{
  "listen": "127.0.0.1:8080",
  "metrics_listen": "127.0.0.1:9090",
  "state_dir": "/absolute/private/toolane-state",
  "tokens": [
    {"token": "replace-with-a-private-random-token", "tenant_id": "local", "tools": ["mock.delay"]}
  ]
}
```

启动后可在服务所在主机运行 `curl -fsS http://127.0.0.1:9090/metrics`。管理监听只允许 `localhost` 或回环 IP，只提供 `GET /metrics`；业务监听不提供这个路径，管理监听也不提供业务 API。管理端口没有 Token 认证，部署时须仅允许受信任的本机进程访问；不要通过反向代理将它公开。未配置 `metrics_listen` 时，不启动管理监听。当前不开放 pprof。

指标采用 Prometheus 文本格式，名称固定，不使用 Execution ID、Workflow ID、Tenant ID、Token 或工具参数作为标签。计数器与耗时直方图从本次服务进程启动起累计，重启会归零；实时 gauge 来自当前 Manager 和 Docker 后端快照。

| 指标 | 含义 |
| --- | --- |
| `toolane_admissions_total{kind,result}` | 单任务或 Workflow 的 HTTP 提交结果；`result` 仅为 `accepted`、`invalid`、`unauthorized`、`conflict`、`capacity`、`unavailable`、`other` |
| `toolane_executions_completed_total{status}` | 持久化状态提交后的终态转换次数，包括恢复时中断的任务 |
| `toolane_queue_duration_seconds` | 从任务接受到进入 `running` 的时间；Workflow 节点含依赖等待 |
| `toolane_execution_duration_seconds` | 从 `process_started_at` 到终态；无后端启动时间时以 `running_at` 为起点；未进入运行的任务不采样 |
| `toolane_cleanup_failures_total` | 清理状态首次转为 `failed` 的次数 |
| `toolane_queued`、`toolane_blocked`、`toolane_pending`、`toolane_running` | 当前就绪队列、依赖阻塞、待启动总量和运行任务数量 |
| `toolane_stored` | 当前 Manager 缓存的任务记录数 |
| `toolane_residual_containers`、`toolane_residual_blocked` | Docker 后端待重试清理的容器数和是否因残留上限暂停沙箱准入；未配置 Docker 时为零 |
| `toolane_reserved_cpu_millicores`、`toolane_reserved_memory_bytes` | 当前沙箱资源预留量 |
| `toolane_halted` | Manager 是否因不可确认的停止或持久化错误暂停准入 |

终态和清理计数只在状态成功写入后更新。HTTP 准入计数按响应状态分类，因此带有效幂等键的重放请求仍属于 `accepted`；它不代表新建任务数。指标采集只保存有限的计数与直方图桶，不保留任务身份。[结构化日志](./V1.0-STRUCTURED-LOGS.md)已单独接入；最终负载实验仍需后续完成。

验证命令：

```bash
go test ./internal/observability ./cmd/toolane ./internal/httpapi ./internal/execution
go test -race ./internal/observability ./cmd/toolane ./internal/httpapi ./internal/execution
```

真实 Docker 服务测试另需 daemon 权限和已拉取的测试镜像，详见 [Docker HTTP 服务](./V1.0-DOCKER-HTTP.md)。

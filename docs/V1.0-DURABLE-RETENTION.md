# V1.0 持久化记录保留与容量控制

第八批为 `NewDurableManager` 增加 SQLite 记录保留边界。默认最多保存 10000 条 Execution，终态记录和事件保留 7 天；可通过 `Config.DurableRecordLimit` 和 `Config.DurableRetention` 调整。一个 Workflow 的每个节点各占一条 Execution 记录。`NewManager` 的进程内保留策略仍由 `RetainedResults` 控制。

## 清理时机与规则

- 启动时先执行资源恢复回调，再清理旧记录，然后重建仍存在的任务与 Workflow。资源恢复失败时不会清理或开放准入。
- 每小时执行一次清理；提交即将达到容量上限时立即清理，为整批新任务预留所需条数。容量充足时，提交只做记录计数查询，避免每次扫描全部快照。因此过期记录在空闲服务中最多等待约一小时才被清理。
- 清理先删除过期幂等键，再删除已超过保留期的安全终态记录。容量不足时，从最早完成的安全终态记录开始删除。执行记录删除时，其事件由数据库外键级联删除。
- 活动任务、活动 Workflow 的全部节点、清理尚未确认成功的任务，以及有效幂等键引用的任务均受保护。终态 Workflow 与节点作为一个整体删除；任一节点仍受保护时，整批保留。
- 若受保护记录已占满容量，新提交返回 `sqlite.ErrRetentionCapacity`；已有有效幂等键的重复请求仍可返回原结果。容量不足属于准入失败，不会使 Manager 进入存储故障暂停状态。

容量上限统计 SQLite 中的全部 Execution 行，包括受保护的活动任务，因此不会让活动任务使数据库记录数无界增长。`RetainedResults` 只限制内存缓存的终态结果；未过期且未被清理的持久化结果仍可从 SQLite 查询。清理完成后，Manager 同步移除对应的内存缓存，避免查询返回已删除记录。

## 验证

SQLite 测试覆盖期限和数量清理、事件级联删除、Workflow 整批删除、活动节点与待清理记录保护、单任务及 Workflow 幂等键保护、过期键释放和删除失败回滚。Manager 测试覆盖满容量拒绝、超大工作流拒绝、重复请求仍命中原记录、重启后保护记录超过新上限，以及清理后内存查询与 SQLite 一致。

本批只实现 Go API 的持久化保留边界；HTTP 和 SSE 服务入口由后续工作接入。

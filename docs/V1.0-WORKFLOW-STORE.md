# V1.0 第五批：Workflow 存储基础

本批为持久化 DAG 提供 SQLite 数据边界。`internal/store/sqlite` 新增 `CreateWorkflow` 与 `GetWorkflow`；本批合并时 `NewDurableManager` 仍拒绝 `SubmitWorkflow`。后续的[第六批](./V1.0-DURABLE-WORKFLOW.md)已接入运行与恢复。

## Schema v3

`workflows` 保存 Workflow ID、租户、状态、原始请求、创建与可选结束时间、版本。`workflow_nodes` 保存节点 ID、提交顺序、JSON 编码的直接依赖、关联的 Execution ID；外键和唯一约束维护归属关系。迁移在同一事务中由 v2 升至 v3，较新 schema 仍会被拒绝。

## 事务边界

`CreateWorkflow` 在一个事务内写入 Workflow、每个节点的 Execution、首个事件及节点关系。任一节点或事件写入失败时整批回滚。存储层检查必需字段和租户一致性；依赖存在性、拓扑排序与状态转换仍由 Manager 负责。调用方只能在提交成功后承认整批任务已接受。

`GetWorkflow` 在只读事务中读取批次以及按提交顺序排列的节点、执行记录和首个事件。后续节点事件可由 `EventsAfter` 按序读取。该接口为后续的持久化调度、重启恢复和查询接口提供数据基础；本批合并时还没有 Workflow 状态更新或运行时接入。

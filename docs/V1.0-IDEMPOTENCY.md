# V1.0 第二批：存储层幂等准入

这一批在 SQLite schema v2 中增加 `idempotency` 表，并提供 `CreateIdempotentExecution`。它把 Execution、首个事件与幂等键记录放在同一事务内提交；任一写入失败，三者均不生效。v1 数据库打开时自动迁移到 v2，原有任务与事件保留。

幂等键作用域为 `tenant_id + endpoint + key`，数据库主键保证唯一。键有效期为首次成功提交后的 24 小时。有效期内，同键且相同请求返回原 Execution ID；同键但不同请求返回 `ErrIdempotencyConflict`。到期后可新建任务，旧任务记录不会因键到期而删除。幂等表以外键限制删除仍受有效键引用的任务，为后续保留策略提供保护。

`record.Request` 必须由调用方在完成参数校验和默认值解析后编码成稳定的规范化字节；存储层对这些字节计算 SHA-256。不同 JSON 字段顺序或等价默认值不会在存储层自动归一化。HTTP 身份解析与请求规范化将在 Manager/API 接入时实现；当前 CLI 与 Manager 仍未使用 SQLite，因此本批尚不提供在线提交幂等。
